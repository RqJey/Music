# mibbi Music — Preview 0.1

Статический музыкальный интерфейс, подготовленный для GitHub Pages. Не требует сборки, сервера или авторизации.

## Запуск локально
Открой `index.html` в браузере. Для корректной работы некоторых возможностей можно запустить локальный сервер (например, расширение Live Server в VS Code).

## Публикация на github.io
1. Создай публичный репозиторий на GitHub.
2. Загрузи в корень репозитория `index.html`, `style.css`, `app.js`.
3. Открой **Settings → Pages**.
4. В разделе Build and deployment выбери **Deploy from a branch**, ветку `main`, папку `/ (root)`.
5. Сохрани. Через несколько минут сайт появится по адресу `https://<логин>.github.io/<репозиторий>/`.

## Что уже работает
- Адаптивный интерфейс, светлая/тёмная/системная тема.
- Локальное воспроизведение аудио и видеофайлов, включая MP4, если формат/кодек поддерживается браузером.
- Очередь из добавленных локальных файлов, перемешивание, повтор, громкость, перемотка.
- Избранное и настройки сохраняются в `localStorage`.
- Поиск-запрос формируется и открывается на публичных страницах YouTube Music, VK Музыки и SoundCloud.
- Для MP4 и других локальных видео есть отдельный видеоплеер.

## Важное ограничение: поиск и проигрывание сторонней музыки
GitHub Pages — это только статический хостинг. Браузерная страница не может надёжно и легально получать полные каталоги/потоки YouTube Music, VK Музыки и SoundCloud простым запросом: у платформ разные API, CORS, ограничения встраивания, авторские права и региональная доступность. Отсутствие необходимости входа на сайте платформы не означает, что они предоставляют открытый API для стороннего агрегатора.

Поэтому текущая версия не притворяется, что умеет выдавать единый список найденных треков или извлекать аудиопотоки: она открывает поиск на каждой площадке. Это честная рабочая отправная точка для следующей итерации.

### Как можно развить интеграции
- **YouTube / YouTube Music:** официальный YouTube Data API для поиска требует API key и имеет квоты; воспроизведение возможно через YouTube IFrame Player для разрешённых видео. Это не гарантирует доступ ко всему каталогу YouTube Music.
- **SoundCloud:** использовать официальный oEmbed/Widgets там, где автор разрешил встраивание; полноценный поиск через API зависит от доступного приложения/ключа и актуальных условий SoundCloud.
- **VK Музыка:** потребуется поддерживаемый официальный API/партнёрский способ доступа. Не стоит строить сайт на неофициальном извлечении потоков — оно может ломаться и нарушать правила сервиса.

Для полноценного единого поиска с секретными ключами обычно нужен небольшой backend/proxy. GitHub Pages сам по себе не умеет хранить секреты. Можно отдельно рассмотреть бесплатные serverless-лимиты (Cloudflare Workers и т.п.), если решим добавить такую архитектуру.

## Структура
- `index.html` — интерфейс
- `style.css` — оформление и адаптивность
- `app.js` — логика плеера, локальные файлы, поиск-ссылки и настройки

Шрифты загружаются с Google Fonts; при недоступности будут использованы системные sans-serif.
